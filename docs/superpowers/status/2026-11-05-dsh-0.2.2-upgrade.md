# 2026-11-05 DSH 0.2.2 适配（preset 挂载 + 锚定工具面 + 通用工具组门）

## 触发

DSH 从 `0.2.1-rc.2` 升级到 `0.2.2-rc.1` 后，本仓 preset 再次 `broken`：

```
tool-subagent-list-agents (@deepseek-ai/dsh-tool-subagent-control/list-agents): never started
```

`~/.dsh/liangshen-anchored-status.json` 里 `liangshen` 与 `liangshen-empty-system` 都是这条；
`minimal-prompt-lab` 正常，peer farm 已由运行时解析重建（linked 26，仅缺可选的
`@deepseek-ai/dsh-workflow-worker-thread`）。

## 根因与修复

### 1. 子路径被删（挂载失败）

0.2.2 的 `@deepseek-ai/dsh-tool-subagent-control` 只导出 `"."`、`"./src/*"`、`"./package.json"`、
`"./locale/*.json"`，不再有 `"./list-agents"`；主插件 `apply()` 现在自己注册
`list_agents` + `send_message` + `interrupt_agent`。

修复：`packages/dsh-liangshen-anchored/presets/liangshen/agent.cordis.yml:392` 给
`tool-subagent-list-agents` 行加 `disabled: !!js` 条件守卫（`require.resolve` 成功才启用），
与可选 `workflow-worker-thread` 行同一写法；行保留（composition 仍是 21 行），
0.2.1 上仍走独立行。变体由 `node tools/sync-preset-variant.mjs --write` 重生成。

### 2. 首请求工具面 / 上下文（0.2.2 运行时变化）

- `SystemPrompt.assemble()` 现在只把 `{sections, contexts, variables}` 交给
  `system-prompt/assemble` waterfall，tools 由 provider 单独收集并在 waterfall 后强制写回
  `{...transformed, tools}`。旧 bootstrap 的 `assembled.tools.map(...)` 在 0.2.2 直接
  `TypeError`（`Cannot read properties of undefined (reading 'map')`），于是完整目录被暴露。
- `working-directory` 的 assemble 监听带 `{prepend:true}` 且在 `await next()` 后无条件把 cwd
  contribution 塞回，preset 侧清空 `contexts` 已压不住它；`refreshContext` 还会恢复
  `required:true` 的 cwd。

修复（`tool-bootstrap.mjs` / `context-gate.mjs`）：

- 工具面：`agent/created` 时用 `agent.ctx.tools.restrict({ allow: bootstrapTools + 压缩后允许项 })`，
  `session/event` 观察到晋升信号时释放，`compaction/end` 后重新收紧；assemble hook 在
  `assembled.tools` 不是数组（0.2.2）时原样返回，不再告警。
- 上下文：`agent/created` 时调用 `agent.ctx.systemPrompt.suppressRuntimeContext()`，并注册
  同名 shadow context `working-directory:current`（`text: ''`、`required: true`）；
  晋升时释放，压缩后重挂。这样首请求 `runtime-context` 消息不再产生，晋升后恢复一条快照。
- 0.2.1 的旧路径保留（assemble 内清空 contexts / 收窄 tools）。

### 3. 工具组通用门（`@mosire/dshom`）

`tools.restrict()` 只过滤**继承来的**全局/祖先工具；`view(scope)` 对**本作用域自己的注册**
无条件放行。dshom 四个特性的工具都注册在 `agent.ctx`，因此 preset 收紧不到它们——
首请求仍是 13 个工具。`register(def, { when })` 的 step-time 门在该运行时实测被丢弃
（直注 host scope 也读到 `when: undefined`），不可依赖。

修复：新增 `packages/dshom/tool-gate.js`，由 dshom 在 Host 入口创建一个共享 gate，
传给它编排的四个特性：

- 锚定预设（`liangshen` / `liangshen-empty-system`）的顶层会话：首次晋升前**不挂载**
  该特性的工具组；`session/event` 观察到 `tool/call` 或 `assistant/message` 后挂载；
  `compaction/end` 后卸载并等待下一次晋升。
- 非锚定预设、子 Agent、已晋升的恢复会话：立即挂载，行为不变。

`job-tools` / `subagent-access` / `prompt-lab-session` / `session-inspect` 的
`maybeInstall` 改为 `gate.mount(agent, mount)`；`forget` 调用 gate 返回的 release。
