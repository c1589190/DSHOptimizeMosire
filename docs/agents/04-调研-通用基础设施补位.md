## 一、结论先行

1. **梁神模式不是「零基础设施」**：它已有 `instruction-hint`（晋升后注入一条 209–211 字符的指令文件清单提示）与 `skill_search` / `skill_load` 两个按需技能工具（`packages/dsh-liangshen-anchored/presets/liangshen/`）。
2. **缺的是通用模式的三类能力**，前两类直接造成失败：
   - **A. 内容 + 自愈**：通用模式注入 AGENTS.md **内容**（含子目录增量），是投影型、压缩后能重注；梁神模式只有**一次性提示**，`compaction/end` 后**不重注**，恢复工作只剩 checkpoint 摘要 → 规则断档。
   - **B. 探测范围/时机**：`instruction-hint` 只在晋升后探测一次「cwd 向上」的指令文件；**cwd 在项目父目录**、或**探测发生在工作区克隆落盘之前**时，一次都不注入；通用模式的 `agent-instructions` 有「触碰子目录文件后发现嵌套 AGENTS.md」+ 压缩重注。
   - **C. skill 发现面**：通用模式每会话注入 skill catalog 并注册 `skill` 工具；梁神只有两个按需工具、无目录，实测**37 个会话里 skill 工具调用 = 0**。
3. **推荐方案 A**：把官方 `@deepseek-ai/dsh-agent-instructions` 与 `@deepseek-ai/dsh-tool-skill` 两行**回挂进预设组合**，继续用现有 `context-gate` + `tool-bootstrap` 把首轮 wire 挡在门外——**首轮锚定不变，晋升后（含压缩重锚后）恢复通用模式行为**。实现以组合配置为主，不写新插件。
4. **代价与口径**：晋升后每会话/每纪元一次性多出 AGENTS.md 基线（本仓现 13,717 bytes；标准会话实测 10,411 chars）+ skill catalog（本机 20 skill 实测 5,321 chars），并让 `skill` 工具进入晋升后工具表；之后**不每请求重复**，只在文件变化/压缩挤掉基线时再发。这与 v7「晋升后也保持极简」的原意相反，需把**铁律 3** 改写为「首轮不注入；晋升后按官方机制恢复内容注入（默认开、可配置关）」。

### 4.1 附带发现（重要纠正，另记）：`complete:true` 的永久性语义缺口

- `persona complete:true` 在 `system-prompt/assemble` 之后**强制只留 persona section**（`dsh-system-prompt/lib/index.js:356-361`），`includeRuntimeContext:false` 强制 `contexts=[]`（:313,348,360）。因此梁神模式**永久**没有：harness identity、cwd（standard 的 persona suffix）、plan policy、team policy、file-reference、全部 tool guidance、deliverable/Web/harness-source、PTC section；**plan mode 规则被永久抹掉**（组合里仍挂 `plan-mode`，其 `section` 永远不渲染）。
- 因此 `context-gate.mjs` 头注释所说「晋升后补一个 runtime-context 快照」在本组合**未发生**（扫描 runtime-context=0）；真正延后到晋升后的是 `time-context`。要恢复快照必须把 `includeRuntimeContext` 改回 `true`（首轮仍可由 gate 清空 contexts，待实测）。
- 这些不属于「AGENTS.md / skill 基础设施」，但属于「通用模式重要基础设施」的旁支；本方案**不处理**，建议另立条目（D-016）做风险隔离，不与本次补位捆绑。
