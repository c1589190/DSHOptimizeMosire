## 〇、结论先行（TL;DR）

1. **梁神模式不是 DSH 官方内置**，而是社区做给 DSH 的 agent preset；核心 = **首轮锚定 + 极简 persona + 工具面渐进披露**。
   官方 DSH（本机 0.2.0-rc.2）全量 grep 无 `liangshen`/`梁神` 命中 `[回代码核过]`。
2. **用户记忆里「被删掉的」是锚定式（anchored standard）那一版**。根因已查清：
   - DSH 0.1.7 起移除 `$DSH_HOME/.agent-presets/<id>/` 目录发现——官方技能原文「**Nothing reads that directory any more.**」
     `[一手文档]` `…/dsh-agent-preset/skills/editing-cordis-compositions/SKILL.md:70`；TUI 源码注释同款「0.1.7 removed directory discovery」
     `[回代码核过]` `…/@deepseek-harness-tui/dsh-tui/lib/types/dsh-adapter/bundled-presets.js:29`。
   - 因此本机 `~/.dsh/.agent-presets/liangshen/`（legacy 目录格式）**不再被任何会话读取**——这就是「被删掉」的直接原因。
   - 此外 dsh-web 插件版在 v0.3.23（2026-09-16）把预设重构为「极简 persona + PTC/both」，`anchorTools` 首轮收窄**正式退役** `[一手文档：dsh-web Release v0.3.23/README]`。
3. **本机残留目录就是锚定式 v7 的完整源码**：9 文件 / 1451 行（8 个有效文件 + 1 个托管元数据），md5 见 §六。
   它与 `@deepseek-harness-tui/dsh-tui@0.15.0` 包内 `presets/liangshen/` **逐字节相同** `[回代码核过：diff -rq 无输出]`。
4. **现代复刻必须走 bundle + `@deepseek-ai/dsh-agent-preset` 声明**（legacy 目录已被移除），这同时从根上修复「被删掉」问题。
   官方技能给的迁移路径：目录名 → `id`，`preset.yml` → `name/description/order`，`agent.cordis.yml` → `plugins`（逐条核对包名）`[一手文档]`。
5. **优化方向已有社区草案**：dsh-web issue #266 的双分支（pro 走锚定 / flash 走弱 persona 神模式）+ 工具开放三档；
   另有 Web 0.4.6 的运行时熔断器（guard）、关键事实登记簿（fact_register）、常驻面守卫（maxResidentTokens）等可借鉴机制。

### 二.1 `tool-bootstrap.mjs`（核心机制）

- 配置契约（`agent.cordis.yml:57-63`）：`bootstrapTools: [bash, str_replace_editor]`、`promoteOn: tool-call`、
  `includeSubagents: true`、`suppressedContextSources: [agent-instructions, skill-catalog]`。
- **注册顺序即语义**：该 row 必须**排在 `agent.cordis.yml` 第一位**，插件 `inject = []`（`tool-bootstrap.mjs:80-108,173`），
  `agent/pre-step` 监听用 `prepend: true`——因为 waterfall after-next 变换按注册逆序执行，先注册 + prepend 才能让「剥离」成为最外层最终变换。
  这是最容易踩坏的一处。
- 两条请求面干预 `[回代码核过]`：
  1. `system-prompt/assemble`：`promotion.status(agent)` 未晋升 ⇒ 把组装工具目录过滤到 keep 集合（缺工具则一次性告警并降级为全目录，绝不让组合漂移变砖）；
  2. `agent/pre-step`：未晋升 ⇒ 过滤掉 `source.kind ∈ suppressedContextSources` 的消息；过滤自身出错 ⇒ **保留全部上下文**（宁可漏剥不可吃用户上下文）。
- `bootstrapMaxTokens` 是**可选**首轮输出上限：出厂不设（Minimal schema 在 adapter 默认 256000 下就能锚定）；
  设了就只在未晋升期注入，晋升后**显式剥掉**（否则会被种子提案带到整会话）。
- `includeSubagents: true`：子代理也走同一套「首轮锚定 → 晋升」；关掉则子代理首轮就拿全目录（`compaction-epoch.mjs:38-43`）。
- 每次进程内按 session 记忆化，冷启动扫一次持久日志，之后 O(1)。

### 二.2 `instruction-hint.mjs`

- 为何：AGENTS.md/CLAUDE.md 摘要是一大块注入，晋升后也会持续扰动轨迹。做法：**晋升后每会话只注入一次 hint**，
  列出命中文件（project 链：`AGENTS.md / CLAUDE.md / AGENTS.local.md / CLAUDE.local.md`；user-global：`$DSH_HOME/AGENTS.md`；
  项目根 = 向上找 `.git/.hg/.svn` 的第一个祖先），并明确「**不要假设内容；任务涉及本工作区时先读相关指令文件再动手**」。
- 落地形式：一条 `user/message`，`source.kind = 'instruction-hint'`（不在 suppressed 集合里，所以不会被剥）。
- 探测走 `ctx.fs` 宿主文件系统缝；服务缺失/探测失败 ⇒ 不注入、不抛。

### 二.3 `skill-search.mjs`

- 为何：`<available_skills>` 目录（多 skill 时约 9KB）会注入首步且每次晋升/压缩后重注，扰动轨迹（issue #6 数据：目录存在时 0/9 锚定）。
- 做法：composition 里**移除 `dsh-tool-skill`**，改挂本插件注册 `skill_search`（按关键词列匹配 skill 摘要，≤20 条）与
  `skill_load`（按精确名字加载一份完整指令，经 `agent.inject` 进下一请求的非唤醒收件箱）。
- 工具描述明确提示模型「本会话没有 skill 目录，怀疑命中就先 skill_search」。

### 二.4 `custom-bash.mjs`（Windows）

- 为何：官方持久 bash 用 PTY，DSH 的 PTY 后端仅 linux/darwin；Windows 上 `subprocess-local` 直接抛「terminal inspection is unsupported on platform win32」。
  而首轮锚定又要求 **`bash` 这个名字 + Minimal 兼容描述**，于是用普通跨平台 subprocess 缝跑 Git Bash，注册**同名同 schema**。
- 解析顺序（显式值唯一候选，未命中就失败而不是猜）：`config.bashPath` / `DSH_TUI_LIANGSHEN_BASH_PATH` → PATH 上的 `git` 反推安装树
  （installer/portable/Scoop 布局，Scoop shim 跟到真身）→ 常见根目录 → Scoop 根 → PATH `bash`。
  **永远拒绝 `C:\Windows\System32\bash.exe`（WSL 启动器）**；apply 时解析一次，全 miss ⇒ 告警并**跳过注册**（让 bootstrap 的缺工具路径降级为全目录，而不是注册一个每次调用都失败的 bash）。
- 语义对齐官方 bash：`bash -c`、新进程、有界输出、非零退出码回报而不 throw；Windows 无 OS 沙箱（landlock 仅 linux），工具描述如实声明。

### 二.5 `compaction-epoch.mjs`

- 压缩会重写模型可见面 ⇒ 压缩后第一条请求是「**第二次首请求**」，必须重新锚定。
- 纪元语义：扫持久事件流，`compaction/end` 记 `boundary = seq` 并把 `promoted` 置 false；只有 `seq > boundary` 的晋升信号才算晋升；无压缩时 boundary = -1（保留一次性语义）。
- 子代理默认视为已晋升（首轮就有工具）；`includeSubagents: true` 时子代理跟随同一相位。

### 二.6 `agent.cordis.yml` 组合要点 `[回代码核过]`

- `persona`：`complete: true` + `includeRuntimeContext: false`；persona 文本**保持与官方 Minimal 逐字节一致**
  （`You are a helpful software engineer assistant.`），并按 `@deepseek-ai/dsh-persona` 版本兼容 `prefix`/`text` 键（`agent.cordis.yml:74-98`）。
- shell：`tool-bash` 全平台 `disabled: true`（与持久 shell 同名冲突）；`persistent-shell` group（`isolate: {terminals: true}`）挂 PTY + `@deepseek-ai/dsh-tool-bash-persistent`（timeout 300000，Minimal 原版描述）；
  Windows 上换 `custom-bash`。
- 文件：`tool-fs` / `tool-fs-search` 走宿主；`bootstrap-filesystem` group（`isolate: {fs: true}`）挂**裸本地 fs** + `str_replace_editor`（maxOutputChars 16000）——即 Minimal 的第二个工具。
- `planning` group（`isolate: {planMode: true}`）：plan-mode 策略段整段保留（含「exit_plan_mode 必为唯一且最后调用」等硬规则）。
- `compaction` group（`isolate: {compaction, toolResultPruner}`）：`compaction-basic` + `command-compact` + 工具结果修剪（threshold 8192 / head 4096 / tail 1024）。
- `delegation` group（`isolate: {workflowEngine: true}`）：可继续的 `subagent` / `subagent_fork`（backgroundMode: continuable）+
  `workflow-ptc` 与 `workflow-worker-thread` **按包是否存在二选一** + `tool-ralph`（maxRounds 64）；codex/claude-code 产品 provider 行保留但 disabled。
- `tool-web`：`fetch: false`（只留 search，且统一 60s 超时）；`tool-todo` 允许并行 in_progress；`tool-job`/`tool-goal`/`tool-ask-user` 均保留。

### 二.7 与 Web 0.4.6 的哲学差异（复刻时必须选边）

| 维度 | 锚定式 v7 | Web 0.4.6 |
|---|---|---|
| 首轮 | Minimal **精确**双工具 + 零注入 | 极简 persona + 原生清单/`run_code` 同驻（无首轮收窄） |
| 工具面 | 首调后**一次性**放开全目录 | 全程同一种呈现；MCP 族**分页**（`tool_activate` 激活） |
| 工具宣告 | 靠宿主组装目录（不注入目录消息） | 注入**持久 user 消息**工具目录（`descriptionMaxLength 200`） |
| AGENTS.md | 晋升后一条 hint，模型自己读 | 宿主 user 角色送达（或 `system-prompt` 模式整段进系统提示） |
| skill | 移除目录注入，改 2 个小工具按需 | 保留目录注入 |
| 运行时纪律 | 无 | `guard` 熔断（停摆/空转）+ `fact_register` 事实登记簿 + working-context 行 + `maxResidentTokens` 守卫 |

> 结论：**锚定式 v7 复刻 = 保真移植**；Web 0.4.6 的 guard/fact_register/分页是**可选优化件**，不是复刻目标。

## 三、为什么锚定有效（一手数据，全部来自 `tool-bootstrap.mjs` 头注释 `[回代码核过]`）

1. **工具 schema 决定锚点**：adapter 默认 maxTokens=256000 时，Minimal 工具对（persistent `bash` + `str_replace_editor`）**5/5 锚定、0 条 `let me` 开头**；
   所有 standard 族 schema（pwsh/read、仅 pwsh、沙箱 bash/read）**11/11 落成 standard-like**。⇒ 首轮必须暴露 Minimal **精确**两件套，而不是 Standard 的 `pwsh`/`read`。
2. **首轮输出预算也影响锚定**：官方端点 1024 cap 下 `We need` 风格 26/32；同一批在 256000 下 0/5。Minimal schema 在 256000 下**无 cap**即可锚定；
   cap 的送达还依赖 profile 包的 `prepareCall`（issue #11 见过被覆盖成 adapter default）。⇒ `bootstrapMaxTokens` 出厂不设、要设须显式释放。
3. **自动注入的提醒会毁掉锚定**：skill 目录存在时锚定**一次都没复现（0/9）**；同一请求去掉后 **~81%**。
   AGENTS.md 摘要同样是大块扰动 ⇒ 首轮剥 `skill-catalog` + `agent-instructions`，晋升后恢复（`instruction-hint` 只给一条 hint）。
4. **对照组**：Web README 引官方脚手架横评——原生面 DeepSWE v1.1 **72.6% vs PTC 67.6%**、Terminal-Bench 2.1 **90.6% vs 85.8%** `[一手文档，转抄]`；
   issue #266 作者称 pro 上 Minimal 锚定 **99/96 vs Standard 91/92** `[一手文档-issue，未回核]`。
   ⚠️ 这些都**不是**本项目的验收证据；本项目的「统计提升」必须自己跑隔离对照（见 §五.11）。
