# D-032：DSH 0.2.2 适配——工具组按晋升挂载（通用门）

**日期**：2026-11-05
**状态**：implemented（未提交；3080 待重启）
**关联**：`docs/superpowers/status/2026-11-05-dsh-0.2.2-upgrade.md`；用户 m00002（升级后适配）、m00813（「工具组通用性问题」）。

## 问题

DSH 0.2.2 后：

1. `@deepseek-ai/dsh-tool-subagent-control/list-agents` 子路径被删，preset 行
   `tool-subagent-list-agents` 报 `never started`，`liangshen` 两预设 `broken`。
2. `SystemPrompt.assemble()` 不再把 tools 交给 `system-prompt/assemble` waterfall，
   旧 bootstrap 收窄工具面失效；`working-directory` 在 waterfall 末尾无条件恢复 cwd，
   清空 contexts 也失效。
3. 即使改用 `tools.restrict()`，dshom 工具注册在 Agent 自己的作用域，
   `view(scope)` 对「本作用域自己的注册」无条件放行，首请求仍是 13 个工具。
4. `register(def, { when })` 的 step-time 门在本机运行时被丢弃（连 Host 作用域直注也读到
   `when: undefined`），不可依赖。

## 决定

- 子路径行保留并加 `disabled: !!js` 条件守卫（`require.resolve` 成功才启用），
  0.2.1 兼容、0.2.2 跳过；变体重新生成。
- 工具面用 `agent.ctx.tools.restrict({ allow })`，晋升释放、`compaction/end` 重收紧。
- 上下文用 `suppressRuntimeContext()` + 同名 `working-directory:current` 空 shadow
  （`required: true`），晋升释放、压缩重挂；0.2.1 旧路径保留。
- **通用工具组门**：`packages/dshom/tool-gate.js`，由 dshom 创建一个 gate 传给四个特性；
  锚定预设顶层会话在首次晋升前不挂载其工具组，晋升后挂载，压缩后卸载；
  非锚定、子 Agent、已晋升的恢复会话立即挂载。特性侧只改 `maybeInstall`/`forget`
  两处（`gate.mount(agent, mount)` / `release()`），不复制锚定逻辑。

## 理由

- 不改 DSH 源码；全部走公开服务（`tools.restrict`、`systemPrompt.suppressRuntimeContext`、
  `systemPrompt.context`、事件流）。
- 工具组门是「工具组通用性」问题：任何 Host 特性只要把工具注册进 Agent 作用域，
  都应该能按会话阶段延迟挂载，而不是各自猜 `when` 是否生效。
- 用事件流判定晋升，与 preset 的 `compaction-epoch` 语义一致（`tool/call` 或
  `assistant/message` 在最后一次 `compaction/end` 之后）。

## 证据

- 单测：liangshen 120、goal-confirm 53、job-tools 18、subagent-access 32、session-import 28、
  prompt-lab-session 12、session-inspect 14、dshom tool-gate 5，全绿。
- 实机 3099：`liangshen` 首请求恰好 `["bash","str_replace_editor"]`、无注入上下文、
  persona 对、晋升 86 工具、`list_agents` 一次；`liangshen-empty-system` 同套全绿。
  证据 `.superpowers/sdd/2026-11-05-dsh-0.2.2/evidence/`。
- 未验证：standard / minimal-prompt-lab 实机、压缩重锚实机、0.2.2 Web 客户端时间标注点验。
